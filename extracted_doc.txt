🧠 AI Mental Health Companion

Technology Stack

LLM + RAG + LangChain + Memory + Output Parser + Transformers + Quantization + Streamlit + optional FastAPI + ngrok

1. Project Idea

AI Mental Health Companion

An AI-powered conversational assistant designed to provide general mental-health information, emotional support, and wellness resources through natural-language interaction.

The system uses an LLM to understand and respond to users, while RAG provides information from a trusted mental-health knowledge base instead of relying only on the model's internal knowledge.

The system also uses LangChain to orchestrate the LLM, retrieval, memory, prompts, and structured output.

The system is designed for general support and education. It does not diagnose mental disorders, prescribe medication, or replace a qualified mental-health professional.

2. Main Goal

The main goal is to build a system that can:

Understand what the user is talking about. 

Maintain the context of the conversation. 

Provide supportive responses. 

Retrieve reliable mental-health information. 

Suggest appropriate general wellness activities. 

Provide relevant sources. 

Handle potentially high-risk conversations safely. 

Return structured information that can be easily displayed by the application.

5. LLM

The Large Language Model is the main generation component.

Its responsibilities are:

Understand the user's message. 

Use the retrieved context. 

Maintain conversational context. 

Generate a natural response. 

Follow the system's safety instructions. 

Produce structured output. 

For example:

User:

"I've been really stressed about my exams."

        ↓

LLM

        ↓

Response:

"It sounds like your exams have been putting

a lot of pressure on you. Would you like to

talk about what feels most overwhelming?"

The LLM alone, however, will not be responsible for factual mental-health knowledge.

That's where RAG comes in.

7. Why RAG?

Suppose the user asks:

"What are common ways to manage stress?"

The system searches the knowledge base and retrieves relevant information.

Then the LLM receives:

User Question

+

Retrieved Context

+

System Instructions

and generates the answer.

This helps make the response grounded in the project's selected sources.

8. Embeddings

Before we can search the documents, we convert the text into numerical representations called embeddings.

For example:

"Stress can affect sleep."

        ↓

Embedding Model

        ↓

[0.21, -0.42, 0.73, ...]

The vector representation allows us to compare the semantic similarity between the user's question and document chunks.

9. Vector Store

The generated embeddings will be stored in a vector database/vector store.

Possible lightweight choice:

FAISS

The flow becomes:

Documents

    ↓

Chunks

    ↓

Embeddings

    ↓

FAISS

    ↓

Similarity Search

When a user asks a question, the system retrieves the most relevant chunks.

11. Conversation Memory

Memory makes the chatbot conversational instead of treating every message as a completely new question.

Example:

User:

"I'm stressed because I have three exams."

AI:

"That sounds like a lot of pressure."

User:

"They're all next week."

User:

"What should I do?"

The system can understand that "they" refers to the exams because previous conversation context is available.

Conceptually:

Current Message

       +

Conversation History

       ↓

     LLM

       ↓

Context-Aware Response

12. Prompt Engineering

We will create a system prompt that defines the assistant's role and behavior.

The prompt will specify that the assistant should:

Be supportive and respectful. 

Provide general mental-health information. 

Use retrieved information when answering factual questions. 

Avoid diagnosing users. 

Avoid prescribing medication. 

Avoid pretending to be a therapist or doctor. 

Encourage professional help when appropriate. 

Follow the safety protocol for potentially high-risk situations. 

This gives us another important part of the project:

Prompt Engineering

13. Output Parser

The LLM normally generates free-form text.

We want structured output.

For example:

{

    "response": "It sounds like you are dealing with a lot of pressure.",

    "topic": "stress",

    "suggested_activity": "breathing_exercise",

    "sources": [

        "Mental Health Resource A"

    ],

    "safety_level": "normal"

}

The Output Parser ensures that the LLM's response follows the expected structure.

14. Why is the Output Parser useful?

Because Streamlit can then use each field separately.

For example:

💬 Response

It sounds like you've been under a lot of pressure.

🏷️ Topic

Stress

🧘 Suggested Activity

Breathing Exercise

📚 Sources

Mental Health Resource A

So the Output Parser isn't just included because it was taught in the course.

It has an actual purpose.

15. Safety Layer

Because the project deals with mental health, safety is a major part of the architecture.

The system first checks the user's message.

User Message

      ↓

Safety Layer

      │

 ┌────┴────┐

 │         │

Normal    High Risk

 │         │

 ▼         ▼

RAG/LLM   Safety Flow

Normal message

"I'm stressed about my exams."

→ Normal AI conversation.

Potentially high-risk message

If the user indicates immediate danger or possible self-harm:

→ The system should not continue with ordinary wellness suggestions.

Instead, it should provide a safety-focused response encouraging the user to contact appropriate emergency/professional support and a trusted person.

The system should never provide instructions that could facilitate self-harm.

17. Quantization

Large language models can require significant memory.

Quantization reduces the numerical precision used to represent model weights.

For example:

Full Precision

      ↓

   8-bit

      ↓

   4-bit

This can reduce memory requirements and make local inference more practical on limited hardware, with trade-offs depending on the model and quantization method.

This is particularly useful for the project because we don't want to depend on a very powerful machine.
